# imbir-mark-up — правила вёрстки

Проект — чистая вёрстка проекта `../imbir-nextjs` (Next.js 16 App Router + TS + Tailwind v4 + svgr).

## Главные правила

1. **Никаких компонентов.** Каждая страница — один файл `app/**/page.tsx` с одним `export default function Page()`, внутри которого вся разметка целиком. Нельзя выносить куски в отдельные функции/файлы, даже внутри одного файла.
2. **Дублирование — это норма.** Хедер, футер, нижнее мобильное меню, сайдбары кабинетов копируются в каждую страницу вручную.
3. **Никакого `.map()`**, никаких массивов данных. Если в макете 8 карточек — в коде буквально 8 карточек, каждая со своими данными.
4. **Никакой логики**: нет `useState`, `useEffect`, хуков, обработчиков событий, валидации, запросов, `"use client"`, условного рендеринга, `clsx`/`cn`. Только статичная JSX-разметка.
5. **Классы Tailwind переносятся из оригинала 1:1** (тема — `app/globals.css`, те же токены `primary`, `foreground`, `secondary`, `muted`, `dim`, `background`, `surface`, `border`, `border-soft`, `overlay`, `info`, `info-tint`). Если в оригинале классы собирались через `cn()`/условия — выбери одно конкретное состояние и запиши итоговую строку классов.
6. **Мобильная и десктопная вёрстка** — переносятся обе, как в оригинале (`md:hidden` / `hidden md:grid` и т.п.).
7. **Интерактив статичен**: активный таб/пункт просто подсвечен классами; дропдауны закрыты (или открыты, если это отдельная страница-состояние); карусели (Swiper) — горизонтальный скролл (`flex overflow-x-auto scrollbar-hide`) с карточками внутри.
8. **Модалки** — отдельные страницы в открытом состоянии (оверлей + панель поверх фоновой страницы или просто поверх `bg-overlay/50`). Путь: рядом с контекстом, с суффиксом `-modal`, например `app/specialists/[id]/review-modal/page.tsx`.
9. **Многошаговые формы** — каждый шаг отдельной страницей: `app/register/doctor/step-1/page.tsx` и т.д.
10. **Не делаем**: loading.tsx, skeleton, error, empty-состояния (кроме `app/not-found.tsx`). Карта Leaflet — заглушка (блок с фоном `bg-surface` и подписью/иконкой). Видеозвонок LiveKit — статичный экран с плитками и панелью кнопок.

## Иконки — svgr

Иконки лежат в `src/assets/icons/<группа>/<имя>.svg` (та же структура, что `imbir-nextjs/src/shared/assets/icons`). Импорт напрямую в страницу:

```tsx
import SearchIcon from "@/assets/icons/header/search.svg";
...
<SearchIcon className="size-5 text-muted" />
```

Если в оригинале иконка была inline-`<svg>` прямо в JSX — переноси inline как есть.

## Картинки

Лежат в `public/images/<группа>/...` (banners, clinics, doctors, hero, services, videos). Подключаем обычным `<img src="/images/doctors/doctor-1.png" alt="..." className="..." />`. `next/image` НЕ используем. Картинки, которые в оригинале приходили с бэкенда (аватары, фото клиник, обложки блога и т.п.), заменяем на эти локальные. Также есть `public/assets/auth-bg.webp` и `public/assets/icons/logo-icon.svg`.

## Ссылки

`<Link href="...">` из `next/link` (или `<a>`). Страницы связаны между собой: «Записаться» → `/record`, карточка врача → `/specialists/1`, клиники → `/clinics/1`, статья → `/blog/example` и т.д. Динамические роуты оставляем с сегментами `[id]` / `[slug]` (страница просто игнорирует params).

## Контент

Правдоподобные русские тексты (Кыргызстан, Бишкек, цены в сомах), бери из `imbir-nextjs/src/shared/dummies/mocks.ts` и из того, что рендерит оригинал. Имена врачей, клиник, отзывы — разные в каждой карточке.

## Эталонные куски

Хедер, футер, нижнее мобильное меню лежат в `_snippets/` (это НЕ компоненты, просто текст для копипаста). Копируй их в страницу дословно, меняя только активный пункт меню.

## Проверка

После работы: `npx tsc --noEmit` в корне проекта должен проходить без ошибок в твоих файлах.
